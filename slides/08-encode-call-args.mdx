<SlideFrame title="encode_call_args" eyebrow="Python → protobuf" dense>
  The `call_id` is illustrative. Callback kwargs are omitted so we can focus on ordinary serializable data.

  ```textproto
  CallFunctionArgs {
    call_id: 9001
    function_name: "user.respond"
    kwargs {
      string_key: "message"
      value {
        value_type { class_ty { name: "user.DiscordMessage" } }
        class_value {
          fields {
            string_key: "from_user"
            value { string_value: "sam" }
          }
          fields {
            string_key: "content"
            value { string_value: "@bamlbot prepare the FFI talk slides." }
          }
        }
      }
    }
  }
  ```
</SlideFrame>

<Notes>
  `respond` is not generic, so `type_args` is empty. The Pydantic model becomes a `class_value`: fields serialize recursively as strings, while `value_type.class_ty` preserves nominal `user.DiscordMessage` identity.
</Notes>
